# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health()` (lines 72-74) | Returns hardcoded `{"status": "ok"}` without checking MongoDB connection; never returns HTTP 503 if the database is unreachable or down. | Stop MongoDB or configure an invalid `MONGO_URI`: `GET /health` still returns HTTP 200 `{"status": "ok"}` instead of 503. | Added `client.admin.command("ping")` within a `try/except PyMongoError` block; returns HTTP 503 if ping fails. |
| 2 | Startup / Indexing (lines 22-28) | No database indexes are created at startup; the starter relies exclusively on the default `_id` index. | Concurrent employee creation or punch-ins create duplicates or race; running query explain shows `COLLSCAN` across all endpoints on 100k records. | Implemented `ensure_indexes()` inside a FastAPI `lifespan` context manager, creating unique and compound indexes idempotently at startup. |
| 3 | `compute_late_minutes()` (lines 33-37) | `punch_in.replace(hour=h, minute=m, ...)` replaces time without timezone awareness; if `punch_in` is UTC, it compares UTC time with IST shift numbers. | Employee with 09:30 shift punches in at 09:40 IST (04:10 UTC); replacement creates 09:30 UTC, producing negative or incorrect minute differences. | Converted `punch_in` to IST (`UTC+05:30`) and constructed `shift_start` datetime explicitly in IST before computing difference. |
| 4 | `compute_late_minutes()` (line 37) | Grace period threshold logic `minutes if minutes > 10 else 0`: at 10 minutes (601 seconds), `int(601/60) = 10`, so the starter returns 0 instead of 10. | Punch in at 09:40:01 IST for a 09:30 shift (601s > 600s grace limit). Rule R2 mandates 10 minutes late, but starter returns 0. | Evaluated `(punch_in - start).total_seconds() > 600`. If strictly greater, returned `int(total_seconds // 60)` elapsed from shift start. |
| 5 | `compute_work_hours()` (lines 40-41) | Uses Python's standard `round(..., 2)` which applies Banker's rounding (round half to even) and float imprecision rather than round half-up. | A duration yielding 4.545 hours rounds to 4.54 with Banker's rounding instead of 4.55 required by Rule R4. | Used Python's `Decimal` module with `ROUND_HALF_UP` to round work hours strictly half-up to 2 decimal places. |
| 6 | `compute_overtime()` (lines 44-47) | Computes any positive minute difference without checking the 30-minute minimum threshold; also fails on overnight shifts where `shift_end` is on the next day. | Punch out 15 minutes after shift end: starter returns 15 overtime minutes instead of 0 (Rule R3 requires >= 30). Fails across midnight. | Calculated difference from shift end (offsetting date by +1 day for overnight shifts); return minutes only if >= 30, otherwise 0. |
| 7 | `create_employee()` (lines 78-85) | Check-then-insert race condition; formats not validated; `created_at` stored as local naive time and returned as datetime object rather than integer epoch ms. | Concurrent `POST /employees` requests with identical `emp_code` both succeed; response `created_at` serializes as ISO string rather than integer epoch ms. | Enforced database unique index on `emp_code`, caught `DuplicateKeyError` (returning 409), stored UTC datetime, and returned epoch ms. |
| 8 | `list_employees()` (lines 89-96) | Pagination bug: `skip = page * page_size` skips items 1-20 on `page=1`; `total` ignores the department filter (`count_documents({})`); results not sorted by `emp_code`. | Request `GET /employees?page=1`: first 20 employees are skipped; filter by department and `total` returns count of entire collection. | Set `skip = (page - 1) * page_size`, passed filter `q` to `count_documents(q)`, and added `.sort("emp_code", 1)`. |
| 9 | `punch_in()` (lines 100-106) | Missing 404 validation: if `emp_code` does not exist, accessing `emp["shift_start"]` raises an unhandled `TypeError` (HTTP 500). | Send `POST /attendance/punch-in` with non-existent `emp_code`: application crashes with 500 Internal Server Error instead of 404. | Added explicit check: `if not emp: raise HTTPException(404, "Employee not found")`. |
| 10 | `punch_in()` (lines 102-105) | Timezone and overnight shift bug (Rule R1): `d = ts.date().isoformat()` uses server local date instead of IST calendar date, and ignores overnight shifts. | Employee with overnight shift 22:00-06:00 punches in at 05:00 IST: record gets today's date instead of previous day's shift date. | Converted timestamp to IST; for overnight shifts where punch-in time < `shift_end`, assigned attendance date to previous calendar day. |
| 11 | `punch_in()` (line 102) | Sub-second truncation bug (Rule R1): starter does not truncate timestamps to whole seconds before calculation and storage. | Punch in with timestamp `1783312500900` ms: stored datetime retains microseconds instead of truncating to whole seconds. | Truncated input epoch milliseconds `(punched_at // 1000) * 1000` before creating UTC datetime object. |
| 12 | `punch_in()` (lines 104-118) | Check-then-insert race condition: `find_one` followed by `insert_one` allows concurrent identical punch-ins to duplicate or overwrite. | Send two simultaneous punch-in requests: both pass `find_one` check and both insert records into `attendance_logs`. | Enforced unique compound index on `(emp_code, date)` and caught `DuplicateKeyError` to return HTTP 409. |
| 13 | `punch_in()` & `list_attendance()` (lines 119-121, 149) | Schema violation: attaches MongoDB `_id` as `"id": str(...)` in response, but OpenAPI contract strictly forbids any `id` field. | Inspect response of `POST /attendance/punch-in` or `GET /attendance`: response contains `"id"`, failing strict contract validation. | Removed `_id` from documents; omitted `"id"` entirely from responses, returning only schema-defined fields. |
| 14 | `list_attendance()` (lines 124-150) | Scalability defect: loads entire collection into Python memory `list(db.attendance_logs.find(q))`, sorts in Python, and slices in memory. | Running `GET /attendance` against 100,000 records exhausts server memory and causes timeouts. | Utilized database cursor with `.sort([("date", -1), ("emp_code", 1)]).skip(skip).limit(page_size)` backed by compound index. |
| 15 | `list_attendance()` (lines 136-141) | Missing range validation: when `date_from > date_to`, starter does not validate and returns 200 with empty list instead of HTTP 422. | Request `GET /attendance?date_from=2026-07-10&date_to=2026-07-01`: returns 200 OK instead of 422 Unprocessable Entity. | Added check: `if date_from and date_to and date_from > date_to: raise HTTPException(422, ...)`. |

## Non-defects Examined

1. **Use of PyMongo Synchronous Client with FastAPI**:
   - We examined whether using PyMongo (synchronous) instead of Motor (async) would block the ASGI event loop. In FastAPI, standard synchronous route handler functions (`def` endpoints) are executed in a separate worker threadpool managed by `anyio.to_thread.run_sync`. Thus, PyMongo calls do not block the event loop or prevent concurrent request handling.
2. **Storing Calendar Dates and Shift Times as ISO Strings**:
   - We verified whether calendar dates (`date`, `joined_on`) and shift times (`shift_start`, `shift_end`) should be converted to BSON datetimes. As detailed in `DATA_MODEL.md` (Section 1), calendar dates and shift times are intentionally stored as strings (`"YYYY-MM-DD"`, `"HH:MM"`) because dates and recurring shift times are not instants; converting them to BSON datetimes would force an arbitrary timezone/date boundary onto them.
